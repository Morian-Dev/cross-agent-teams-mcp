| Error propagation | **WARN (INT-01)** | `runQuietGuard` exceptions bubble through `Promise.all` in `fanoutAutoPoke` (src/mcp/auto-poke-fanout.ts:41) and are not caught; they propagate out of `send()`/`broadcast()`, past `wrapStorage` (which only catches SQLite errors — src/daemon/errors.ts:11), and fail the entire tool call. This contradicts design.md §3 "guard 失败 → 降级为纯 mailbox … 比'抛 error 整个 send 失败'安全得多". The mailbox is already persisted at that point (good), but the caller sees an unhandled exception instead of a structured `poked: false` with `guard_failed`/`tmux_unavailable`. Recommend wrapping the guard+poke block in try/catch, mapping exceptions to `{ agent_id, reason: 'guard_failed' }` (or adding a new `reason: 'tmux_error'`). |
| Encoding at boundary | PASS | `capturePaneTail` returns UTF-8 stdout; hash comparison is string-equal, no encoding conversion issues. |

### Findings by Severity

**CRITICAL** (must fix): none

**WARNING** (should fix):

- **INT-01** `src/mcp/auto-poke-fanout.ts:41` — guard/pokeFn exceptions propagate unhandled through `Promise.all`, violating design.md §3's "never throw, always fall back to mailbox" contract. Recommendation: wrap per-recipient body in try/catch, map thrown errors to `{ agent_id, reason: 'guard_failed' }`.
- **INT-02** `src/daemon/tmux-cli.ts:19` — `capturePaneTail` has no timeout; a hung `tmux capture-pane` subprocess will stall the guard indefinitely. Recommendation: add an `execFile` timeout (e.g. 2 × POKE_QUIET_MS) to bound each capture.

**SUGGESTION** (consider): none
