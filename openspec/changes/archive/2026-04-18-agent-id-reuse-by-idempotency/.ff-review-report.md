## Stage 2: Code Quality — WARN

### 发现

**WARNING 1 (minor, 非阻断): `fanout.rebind` fallback 分支在 tools.ts:168 是 dead code.**
- `src/mcp/tools.ts:167-169`: `else if (fanout) { try { fanout.rebind(...) } catch { /* best-effort */ } }`
- 这个分支仅当 `onRegisterSuccess` 未传但 `fanout` 传入时执行. 在生产代码路径里 `transport.ts:82` 始终传 `onRegisterSuccess`; 测试也都通过 `onRegisterSuccess`. 此 fallback 实际上永远不会走到.
- 建议(非阻断): 后续 change 统一收紧为单一入口, 或把 `fanout` 参数也去掉.

**WARNING 2 (minor, 非阻断): `RegisterAgentService.connections` Map 的 cross-session 防护作用有限.**
- `RegisterAgentService` 在 `registerBusinessTools` 内 per-session 实例化 (tools.ts:78), 因此每个 session 有独立的 `connections` Map.
- 由于 `connection_id === sessionId` (tools.ts:153 `getSessionId() ?? caller()`), 单个 session 只会有一个 connection_id, 所以 identity-map 里同 key 不会出现不同 connection_id 的情况.
- 结论: `connections` Map 的 collision 保护在当前生产路径上基本不会触发. 但它并未引入 bug (spec 明确跨 session 复用是 legitimate, 并由 `sessionOwners` authHash 做同 session 真防护).
- 建议(非阻断): 后续 change 可评估简化: 或把 RegisterAgentService 提到 mountMcp 作用域 (让 collisions 跨 session 真生效), 或移除 `connections` Map 转为纯 delegate. 当前实现符合 spec 文字, 通过所有测试, 故不作为 critical.
