- Function lengths: no function exceeds 50 lines after excluding decorators/type noise. `registerBusinessTools` is long as a whole (~270 lines) but it is a flat sequence of `server.registerTool(...)` calls with no branching depth.

## Stage 3: Integration (CRITICAL)

**Positive findings:**
- Full transport dispatch works: `mountMcp` registers exactly 14 business tools (verified by enumeration in tools.ts: register_agent, list_agents, send_message, broadcast, get_inbox, task_add, task_claim, task_complete, task_list, register_contract, subscribe_contract, get_contract, diff_contracts, pending_contract_events) plus echo = 15 tools.
- Session lifecycle: `createSession` builds transport+server pair, sets onsessioninitialized to update the per-session `AgentIdHolder`, and onclose removes from the `sessions` map. Unknown session id -> 400 unknown_session is enforced for POST/GET/DELETE handlers.
- Cleanup interval wiring: `cleanupIntervalMs` (opt override or env CLEANUP_INTERVAL_MS) creates setInterval, `interval.unref()` so vitest doesn't leak, onClose hook clearInterval + db.close. Verified by tests/cleanup-interval.test.ts.
- Auth hook correctly exempts `/health`, honors Bearer and `?token=` query, returns 401 invalid_token envelope.
- 100 concurrent register_contract calls converge to versions 1..100 gap-free (register-contract-concurrent.test.ts) - `.immediate()` transaction is effective.
- phase2-e2e.test.ts uses the real @modelcontextprotocol/sdk Client over StreamableHTTPClientTransport across three concurrent sessions and completes the full register->broadcast->inbox->task-lifecycle flow.

**CRITICAL integration defects:**
1. **SSE fanout unwired** (see CRITICAL #2 in frontmatter). The SseFanout class is an orphaned primitive. No production path from `register_contract` to a live SSE session subscriber exists. The contract-subscriptions spec explicitly says "the daemon MUST push ... to every live SSE session in that team that has subscribed". In production this push is dead code.
2. **last_seen_at wiring missing** (see CRITICAL #1). Consequences compound: cleanup.ts floor computation uses `WHERE last_seen_at >= onlineThreshold` - if no tool call ever updates it, after register_agent the clock is the last write; 5 minutes later every agent is 'offline' and cleanup deletes events agents still need.
3. **identity guard never invoked** (CRITICAL #3). Design note: since tools never accept client-supplied agent_id parameters, the 403 path is structurally unreachable via the current tool schemas. But the spec text requires the daemon to return 403 - if this is accepted as "prevented by design", downgrade to WARN; if strict, this is CRITICAL. Recording as CRITICAL for completeness.

**No race conditions or leaked handles observed** beyond the above.

## Summary

- Counts: 3 CRITICALs, 7 WARNINGs.
- Headline: implementation is strong on DB/service primitives and schema/diff logic, but three spec requirements remain un-wired into the request path (touch, SSE fanout push, identity/409 HTTP status). The 84-test suite passes only because each missing wiring is tested at the primitive level, not at the request path.
- Recommended follow-up: wire AgentsRepo.touch() into a per-tool post-hook in tools.ts; instantiate SseFanout in server.ts and pass it into RegisterContractService so emitContractEvent fires on commit; map `{error:'agent_id_collision'}` to HTTP 409 at the transport layer.

See frontmatter for the structured warning/critical list. Archival is NOT recommended before the three CRITICALs are addressed.
