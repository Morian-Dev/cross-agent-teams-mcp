### WARNINGs (2)

- **W1**: `createAutoPokeImpl(db, _agents: AgentsRepo)` — the `_agents` parameter is **never used** inside the factory (the impl goes directly to `db.prepare('SELECT display_name …')`). Reason: `AgentsRepo.findById` returns only `{agent_id, team}` and doesn't expose `display_name`, so the raw prepared statement is pragmatic. But the `_agents` parameter is pure dead weight in the public signature — either (a) drop the param and update the single caller at line 74, or (b) add a `findByIdWithDisplayName` method to `AgentsRepo` and use it, keeping the dependency explicit. As-is it violates "no unused vars" hygiene even with the underscore prefix (underscore indicates "intentionally ignored in a callback"; in a factory's required positional param list, it reads as a leftover).
- **W2**: The design doc (lines 77-82) explicitly said "在 `autoPokeImpl` 外层闭包 (createMcpServer scope) 拿 `agents` repo ref, 每次 autoPokeImpl 内 `agents.findById(args.fromAgentId)` 一次". The implementation deviates by inlining a raw SQL query. Not a bug (spec scenarios all pass), but the deviation is undocumented in tasks.md or design.md. Consider either patching AgentsRepo to expose display_name, or amending design.md to note the inline-SQL choice.

No dead code or unused imports introduced elsewhere. Pre-existing unused-var items (`sse-fanout.ts:22`, `broadcast.ts:39`) are not aggravated.
